# ExcaliDash Role

Deploys [ExcaliDash](https://excalidash.xyz/) - self-hosted Excalidraw with accounts, per-drawing sharing and live collaboration - using Podman with k8s files. Uses the upstream `zimengxiong/excalidash-backend` and `-frontend` images, run as a single two-container pod backed by the shared PostgreSQL.

Variables: [defaults/main.yml](defaults/main.yml)

This role replaces the stateless `excalidraw` role: [tasks/legacy.yml](tasks/legacy.yml) removes its service, project directory and vhost on the first deploy. Drop it once every host has been redeployed.

## Prerequisites

The `podman` role, the `postgres` role (shared instance, deployed first) and `nginx` when `excalidash_nginx_enabled`. Order them before `excalidash` in the playbook for fresh installs. The role creates its own `excalidash` database and a minimal-privilege user (`NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`, `ALL` on its database only).

Four secrets are required, none of them have defaults:

```yaml
excalidash_postgres_password: "{{ vault_<host>_excalidash_postgres_password }}"           # min 12 chars
excalidash_jwt_secret: "{{ vault_<host>_excalidash_jwt_secret }}"                         # min 32 chars
excalidash_csrf_secret: "{{ vault_<host>_excalidash_csrf_secret }}"                       # min 32 chars
excalidash_api_key_hash_pepper: "{{ vault_<host>_excalidash_api_key_hash_pepper }}"       # min 32 chars
```

Generate each with `openssl rand -hex 32`. `excalidash_api_key_hash_pepper` can never change without invalidating every API key.

## First Login

Create the administrator **immediately after the first deploy**, before anyone else can reach the hostname. On a fresh instance the first visitor is offered the setup flow; the admin form requires a one-time bootstrap code from the backend logs (valid 15 minutes, restart the backend for a new one):

```sh
podman logs excalidash-backend 2>&1 | grep -A3 'BOOTSTRAP SETUP'
```

Choose **Enable Authentication**, never **Keep Disabled**: without auth everyone shares one workspace. The role sets `AUTH_MODE=local` explicitly.

Then open **Admin** from the account menu to create users and turn **self-registration** off (check its state: it is a runtime toggle, not a role variable).

## Sharing

From a drawing's **Share** dialog (or a collection's context menu):

- invite an account with **View** or **Edit** access (authenticated, listed under *Shared with me*);
- or switch **Link access** from *Restricted* to *Anyone with the link* - **no login required** for whoever holds that URL. Set an expiry and revoke it when done.

Live cursors and follow mode work over `/socket.io/`, proxied through nginx.

## Storage

Everything lives in the `excalidash` PostgreSQL database: accounts, drawings, collections, sharing settings, version history and uploaded images (the backend stores files in the database by default). The pod keeps no state of its own: `/app/prisma` in the backend only holds files its entrypoint regenerates at every start, so there is no host data directory and no userns mapping.

The backend runs `prisma migrate deploy` at every start. `DATABASE_URL` (password URL-encoded) is rendered into the pod manifest, which is mode `0600`.

## Ports

| Port                      | Protocol | Purpose                                     |
| ------------------------- | -------- | ------------------------------------------- |
| `excalidash_port` (8100)  | tcp      | Frontend (nginx) on host loopback only      |

The backend (8000) is only reachable inside the pod. The frontend proxies `/api/` and `/socket.io/` to it over the pod's loopback. The backend reaches PostgreSQL on the host's loopback through the pasta gateway (`excalidash_postgres_host`, `{{ podman_gw_gateway }}`); `pg_hba` sees it as `127.0.0.1`.

## Nginx Reverse Proxy

Set `excalidash_nginx_enabled: true` and `excalidash_nginx_hostname` to expose it over HTTPS. The vhost keeps the public `Host` (the backend checks the Origin against `excalidash_frontend_url`) and upgrades WebSockets. TLS is opt-in:

- `excalidash_nginx_letsencrypt: false` (default) — use the shared self-signed cert (`nginx_default_ssl_cert`, generated by the `nginx` role). Required for internal names like `*.nas.local`.
- `excalidash_nginx_letsencrypt: true` — provision a Let's Encrypt cert via the shared `nginx` role's certbot tasks. Requires a publicly-resolvable hostname with a DNS record pointing at the host, and `acme_email` set.

`excalidash_trust_proxy` is `2` (host nginx + the frontend container's nginx). Adjust it if the proxy chain changes.

## Backup

Nothing to add: the shared `postgres: all` job in the inventory dumps the `excalidash` database (`pg_dump -Fc`). The secrets live in the vault, not in the backup. **Settings → Export backup** in the UI gives a per-account `.excalidash` archive, which does not include accounts or sharing settings.

Restoring is a regular `pg_restore` of the `excalidash` database, then a backend restart.

## Upgrade

Take a backup, bump `excalidash_version` (backend and frontend always share one tag), and redeploy with `--tags excalidash`. Migrations run on the backend's next start. Release notes: <https://github.com/ZimengXiong/ExcaliDash/releases>.

## Troubleshooting

```sh
systemctl --user status excalidash
journalctl --user -u excalidash -f
podman logs excalidash-backend
podman logs excalidash-frontend
```

- **Backend exits with a Prisma / `P1001` / `P1000` error** — database unreachable or wrong credentials. Check `excalidash_postgres_*`, that `postgres` listens on `127.0.0.1` and that the password in the vault matches the role's (the role re-sets it on every run).
- **`permission denied for schema public`** — the schema grant task did not run; redeploy the role.
- **Frontend exits with `bind() to 0.0.0.0:80 failed (13: Permission denied)`** — the image listens on 80 and 8080 unconditionally, and rootless podman keeps ports < 1024 privileged. The pod manifest lowers `net.ipv4.ip_unprivileged_port_start` to 80 in the pod's own network namespace (host sysctl untouched).
- **502 from nginx while `systemctl --user status excalidash` says active** — the unit stays up as long as one container runs, so a dead container does not fail it. Check `podman ps -a --filter name=excalidash`.
- **Drawing loads but edits don't sync** — check the WebSocket upgrade in the vhost, that the browser URL matches `excalidash_frontend_url` exactly, and that the collaborator has *Edit* access.
- **Login loop or CSRF errors** — usually `excalidash_frontend_url` not matching the browser origin, or a wrong `excalidash_trust_proxy`.
