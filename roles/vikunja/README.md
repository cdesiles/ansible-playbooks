# Vikunja Role

Deploys [Vikunja](https://vikunja.io/) - to-do lists, kanban boards and projects with CalDAV sync - using Podman with k8s files. Uses the upstream `vikunja/vikunja` image (one binary serves the API and the frontend) as a single-container pod backed by the shared PostgreSQL.

Variables: [defaults/main.yml](defaults/main.yml)

## Prerequisites

The `podman` role, the `postgres` role (shared instance, deployed first) and `nginx` when `vikunja_nginx_enabled`. Order them before `vikunja` in the playbook for fresh installs. The role creates its own `vikunja` database and a minimal-privilege user (`NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`, `ALL` on its database only).

Two secrets are required, neither has a default:

```yaml
vikunja_postgres_password: "{{ vault_<host>_vikunja_postgres_password }}" # min 12 chars
vikunja_service_secret: "{{ vault_<host>_vikunja_service_secret }}" # min 32 chars
```

Generate each with `openssl rand -hex 32`. `vikunja_service_secret` signs sessions and link shares: changing it logs everyone out.

No Valkey: Vikunja keeps its cache and key-value store in memory, which upstream recommends below a handful of users.

## Accounts

Self-registration is off by default, so a public vhost exposes no sign-up form. Create accounts with the CLI (it prompts for the password):

```sh
podman exec -it vikunja /app/vikunja/vikunja user create -u <username> -e <email>
podman exec vikunja /app/vikunja/vikunja user list
```

There is no instance admin in the community edition: each account owns its projects and shares them through teams or links (`vikunja_enable_link_sharing`).

Without the mailer (`vikunja_mailer_enabled: false`), accounts are active immediately, there are no email reminders, and passwords are reset from the CLI:

```sh
podman exec -it vikunja /app/vikunja/vikunja user reset-password <id> --direct
```

## CalDAV

**Settings → CalDAV** shows the URL (`https://<hostname>/dav/principals/<username>/`) and issues per-device tokens. Accounts with TOTP must use a token: Vikunja rejects their password over basic auth. Turn the endpoint off with `vikunja_enable_caldav: false`.

## Storage

- `vikunja` PostgreSQL database: accounts, projects, tasks, comments. Migrations run at every start.
- `vikunja_files_dir`, mounted at `/app/vikunja/files`: attachments, project backgrounds, uploaded avatars. Owned by `{{ ansible_user }}` on the host: the pod maps the rootless user onto the image's UID/GID 1000 (`keep-id`), so the process is not root in the container.

The pod manifest (mode `0600`) carries the database password and the service secret as environment variables.

The image is `FROM scratch`, with no shell and no `curl`. The pod has no liveness probe, because podman runs `httpGet`/`tcpSocket` probes with `curl`/`nc` inside the container.

## Ports

| Port                  | Protocol | Purpose                                 |
| --------------------- | -------- | --------------------------------------- |
| `vikunja_port` (3456) | tcp      | API and frontend, on host loopback only |

Vikunja reaches PostgreSQL on the host's loopback through the pasta gateway (`vikunja_postgres_host`, `{{ podman_gw_gateway }}`); `pg_hba` sees it as `127.0.0.1`. Webhooks, avatar downloads and imports cannot reach that gateway: Vikunja's SSRF guard denies non-routable ranges, `100.64.0.0/10` included, while `outgoingrequests.allownonroutableips` stays off (the default).

## Nginx Reverse Proxy

Set `vikunja_nginx_enabled: true` and `vikunja_nginx_hostname` to expose it over HTTPS; `vikunja_public_url` follows the hostname. The vhost upgrades WebSockets (live notifications) and caps uploads at `vikunja_files_max_size_mb`, the limit Vikunja applies too. TLS is opt-in:

- `vikunja_nginx_letsencrypt: false` (default) — use the shared self-signed cert (`nginx_default_ssl_cert`, generated by the `nginx` role). Required for internal names like `*.nas.local`.
- `vikunja_nginx_letsencrypt: true` — provision a Let's Encrypt cert via the shared `nginx` role's certbot tasks. Requires a publicly-resolvable hostname with a DNS record pointing at the host, and `acme_email` set.

Vikunja takes the client IP from `X-Forwarded-For` (`ipextractionmethod: xff`), for its per-IP login rate limits and its logs.

## Backup

Restore the database and the files from the same night:

- the shared `postgres: all` job in the inventory dumps the `vikunja` database;
- a job on `vikunja_backup_paths` covers the files:

```yaml
backup_jobs:
    - name: vikunja
      repositories: [offsite]
      paths: "{{ vikunja_backup_paths }}"
      schedule: "*-*-* 02:15:00" # daily, after the database dump
```

Restoring is a regular `pg_restore` of the `vikunja` database plus the files directory, then a restart. The secrets live in the vault, not in the backup. Deleted tasks and projects sit in the trash for 30 days; past that, only a backup brings them back.

## Upgrade

Take a backup, bump `vikunja_version`, and redeploy with `--tags vikunja`. Migrations run on the next start. Release notes: <https://github.com/go-vikunja/vikunja/releases>.

## Troubleshooting

```sh
systemctl --user status vikunja
journalctl --user -u vikunja -f
podman logs vikunja
podman exec vikunja /app/vikunja/vikunja doctor
```

`doctor` checks the database connection, the files directory's writability and user namespace mapping, and the SMTP connection when enabled.

- **Exits at startup with a database error** — database unreachable or wrong credentials. Check `vikunja_postgres_*`, that `postgres` listens on `127.0.0.1` and that the password in the vault matches the role's (the role re-sets it on every run).
- **`permission denied` under `/app/vikunja/files`** — the `keep-id` mapping no longer matches the image's user. Check `vikunja_container_uid`/`_gid` against the image's `USER`.
- **Every client logged with the same IP, login rate limit shared** — pasta delivers nginx's connections from the pod's public address, the host's default-route address. `X-Forwarded-For` is trusted from loopback, link-local and private addresses only: if that address is public, add it to `vikunja_trusted_proxies` as `<ip>/32`.
- **CalDAV client rejects valid credentials** — the account has TOTP: use a CalDAV token.
